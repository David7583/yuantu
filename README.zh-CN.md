# 源图 Yuantu
### 可溯源的混合检索知识底座

*Read this in [English](README.md).*

> 在不可变的原始资料之上做混合检索（语义、事实、关系与定位），提供受治理、可追溯的知识层。面向政策分析、访谈研究等对结论出处有严格要求的场景。

**项目状态：** 研究原型，非即用型产品。理解层（四个数据库）已完成，行动层开发中。

## 简介

源图（Yuantu）处理的是非标、异构、长期积累的文本资料，典型如政策文档、访谈记录。这类资料规模大、结构松散，直接交由大模型检索时，输出往往既不可信也不可追溯。该问题与近期的同类工作面向同一方向，例如 Andrej Karpathy 提出的 LLM Wiki、知识图谱增强检索（GraphRAG）。

源图的设计区别于将源材料压缩为模型生成"知识页"的做法。在源图中，原始材料保持不可变，并作为全系统唯一权威来源；模型只在其上建立索引，不改写原文。系统对外输出的每一条内容，均显式区分"可溯源的确定引用"与"模型生成的推断"。

据此，源图不是一个自主 agent，而是面向 agent 生态的知识基础设施，即一个可被上层调用、但本身严格受治理的可信知识层。

## 背景

本项目源于政策与区域研究中的一项实际约束：一个结论若不能被追溯到其原始出处，便无法在严肃分析中使用。可追溯性因此不是附加功能，而是系统的第一设计目标，并由此推导出下述全部原则。

## 设计原则

- **数据层唯一权威。** 所有事实仅有一个来源，即不可变的原始材料。各层索引均为其派生视图，不得篡改或替代原文。
- **单向数据流。** 信息只从原始材料流向索引层，不允许逆向写回，以保证任意输出均可沿固定路径回溯至源头。
- **制度优先于能力。** 模型在系统中作为受注册、调用与审计的能力存在，而非自主决策者；其输出始终受可溯源、可区分的边界约束。
- **引用与生成分离。** 系统对外输出显式标注每条内容属于"有出处的引用"或"模型生成"。

## 系统架构

系统分三层，层间仅存在单向数据流。

| 层 | 职责 | 实现 |
| --- | --- | --- |
| 数据层 | 原始资料的唯一权威来源，只读不改 | 原始 JSON |
| 理解层 | 在原文之上建立多重索引，支持混合检索 | 四个数据库，见下表 |
| 行动层（开发中） | 受治理的能力注册与调用 | 四数据库（与理解层同构） |

理解层由四个数据库构成，通过混合检索整合语义、事实、关系三个维度，并遵循"先定位、再取证"的逻辑：先经 SQLite 定位到目标单元，再到三轴取相应证据。其中三轴从相互独立的角度描述同一份材料，SQLite 承担标识、元数据与定位，是检索的入口层。

| 数据库 | 角色 | 说明 |
| --- | --- | --- |
| SQLite | 定位与元数据 | 标识、别名与路径映射；检索的入口与定位层 |
| ChromaDB | 语义轴 | 向量化的语义相似检索（BAAI/bge-m3） |
| DuckDB | 事实轴 | 结构化事实，千万行量级 |
| Neo4j | 关系轴 | 实体与叙事关系图谱 |

四库各自独立，互不混合。

## 工作流程

理解层的处理管线大致分为几个阶段：

1. **承认（数据入口）。** 原始导出（如 ChatGPT 对话 JSON）被承认进入数据层，获得系统认可的数据资产身份。系统起源于数据层，这一步是从原始数据通往理解层的入口阀门。
2. **结构解析。** 通过裁决的资产被解析为带稳定段句索引与字符坐标的结构文本单元——纯结构解析，不引入任何 NLP 模型。
3. **标准化与分析。** 单元被标准化为标准文本单元，随后进行结构分析（统计、邻接、共现、层级）与频率分析。
4. **登记。** 通过制度裁决的单元被登记为系统级结构对象，并赋予稳定 ID。
5. **入库。** 已登记单元及其关系被装入三轴：关系入 Neo4j，结构化事实入 DuckDB（由 SQLite 同步），语义向量入 ChromaDB。

每个阶段都写入可审计的运行元数据，且任何阶段都不改写原文。

## 仓库结构

- `scripts/` —— 管线代码，按层级与阶段组织：数据承认、锚定/入库、结构分析、图构建、向量管线、数据库同步。
- `data/`、`derivation/`、`chromadb/` —— 处理后数据、派生数据库产物与向量的去向。系统在运行时写入此处；本仓库中以空骨架形式提供。
- `config/` —— 连接与策略配置。不包含在本仓库内（见"环境与安装"）。

## 环境与安装

理解层依赖 Python 标准库，外加少量第三方包：

```
pip install pyyaml neo4j duckdb chromadb sentence-transformers
```

（`sentence-transformers` 仅本地向量模式需要；若改用 OpenAI 兼容的向量接口则无需安装。）

另需一个运行中的 Neo4j 实例（默认 `bolt://localhost:7687`）。

配置与策略文件——数据库连接、解析/噪声/重要性策略、向量后端——由使用者自行提供，**不包含**在本仓库内。凭证从不写入代码：Neo4j 密码按 `--password`、`NEO4J_PASSWORD` 环境变量、连接配置文件的优先级读取；向量 API 的 token 从一个由配置指定名称的环境变量中读取。脱敏的示例配置与策略文件将后续补充。

本项目为研究原型，并非一键安装；完整复现整条管线需要上述源数据与配置。

## 项目状态

本项目持续开发约 18 个月，处理一份真实的长期语料（约 2,170 条记录，377 MB）。

| 模块 | 状态 | 说明 |
| --- | --- | --- |
| 理解层四库 | 已完成（2026-03） | 语义、事实、关系三轴闭环，配合 SQLite 定位层；事实轴千万行量级；关系轴约 18 万节点、约 23 万关系，保留原始叙事顺序 |
| 行动层 | 开发中 | 能力注册与受治理调用的核心框架已实现并跑通（含真实大模型 API 调用）；交互与查询层若干组件待补 |
| 可信度度量 | 实验性 | 跟踪两项指标：输出中确定引用与模型生成内容的比例，以及资料随时间的"半衰期" |

源图目前为研究原型，非即用型产品。

## 方法与说明

实现过程借助大模型协作完成，但全部架构选择由人决定；工具被作为材料而非权威使用，这与系统对待模型的方式一致。项目的核心产出是架构判断，代码是这些判断的实现。
